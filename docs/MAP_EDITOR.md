# マップエディター

開発サーバーで `/review.html` を開くと、家とダンジョン階を編集できます。マップJSONはv6で、パレットの座標を保存せず`assetId`と`frame`だけを保存します。そのため、パレットを後から並べ替えても既存マップの見た目は変わりません。

## 素材と自由配置パレット

素材シートは `assets-src/map-tiles/sheets/` にPNGと同名の`.tileset.json`を組で投入します。生成手順と設定項目は [MAP_TILE_PIPELINE.md](MAP_TILE_PIPELINE.md) を参照してください。

エディター右側はパレット専用です。ページとパレット内タイルを画像グリッドで選び、ページ名は補助表示として扱います。マップ下部の「素材フォルダ（Project）」に取り込んだスプライトシートが並び、素材画像を選んでからシート下の方眼で単体または矩形を選択し、右側のパレットへドラッグして置きます。パレット内は空白を含む任意の配置で、ユーザーがダンジョン用・インテリア用など好きな大きなパレットを手動で作成できます。

- パレット上のドラッグで矩形を選択する。
- 選択範囲をドラッグすると移動し、`Shift`を押しながらドラッグすると複製する。
- `Delete`で選択セルを消去する。ページの縮小は、縮小範囲に素材が残っていると拒否される。
- ページは家/ダンジョン、16px/32pxごとに分かれ、1ページに多数の素材を集約できる巨大な作業面です。新規ページは2048×2048セルで作成し、必要に応じて最大4096×4096セルまで拡縮できます。追加、改名、拡縮、削除、Undo/Redoは手動で行います。
- 巨大なページは素材が存在する左上の作業範囲だけを等倍表示し、端へ素材を置くと表示範囲が自動的に広がります。ページ全体を縮小画像として描画しないため、16px/32px素材の画質は保持されます。
- 開発中は「保存」が`PUT /__map-editor/palettes`へ保存する。本番ビルドではJSON書き出しのみを提供する。

パレットの矩形選択はマップ上のスタンプです。鉛筆は選択範囲の左上を配置し、矩形ツールは範囲内で繰り返します。空白セルはマップ上の既存タイルを消しません。スタンプの素材セルがマップ外へ出る操作は、部分的に配置せず拒否されます。塗りつぶしは単一セル選択時のみ使えます。

左メニューの「レイヤー」で作業対象を選びます。配置、消去、スポイトは選択中の`ground`、`structure`、`decoration`のいずれかだけに作用します。各レイヤーの表示チェックはキャンバス上の可視状態だけを切り替え、保存済みのセルは削除しません。パレット配置では通行設定を変更せず、通行可否は道具の「通行可」「通行不可」で明示的に編集します。どちらも鉛筆と同様に、押したままドラッグして連続したセルを設定できます。「通行表示」をオンにすると可否を青／オレンジのオーバーレイで確認できます。

## マップ設定とマーカー

ツールバーの「一覧表示」はマップ一覧を切り替えるだけで、編集対象を変更しません。「マップ種類」「幅」「高さ」「セル」は新規作成と「サイズを適用」の設定値です。既存マップの種類変更は、タイル・collision・マーカーがすべて空の場合だけ可能です。家へ変更する場合は既存の家がないことを確認し、ダンジョンへ変更する場合は次の階数を割り当てます。種類・セルサイズ・幅・高さは一つの操作として適用され、どれかが拒否された場合は何も変更しません。

幅・高さは4〜256セルです。サイズの縮小は左上を保持し、切り落とす範囲にタイル、通行可設定、またはマーカーがある場合は拒否されます。セルサイズの変更は、タイル・collision・マーカーがすべて空のマップにだけ可能です。大きなマップはブラウザのcanvas上限を超えないよう自動縮小表示されますが、セル座標と編集操作は変わりません。

家には`homeSpawn`、`dungeonEntrance`、`homePreparation`、`homeVisitors`が必要です。店の動線には`shopkeeperCounter`と`customerCounter`を使います。保管・陳列はゲーム内メニューから行うため、専用マーカーはありません。ダンジョンの各階には`stairsUp`が必要で、次階がある場合は`stairsDown`も必要です。階段はパレットで単一セルを選んでから配置し、そのセルが階段の見た目としてマーカーに保存されます。

ツールバーの「地下階」で選択中のダンジョンを地下1階、地下2階のように指定できます。既存階へ移動すると、間にある階は自動的に前後へずれて、1階からの連続性と階段接続を維持します。

「編集マップでゲーム開始」は家と全ダンジョン階を一つの実行パックとしてブラウザーへ保存し、その編集内容を使ってゲームを開始します。ダンジョン階は1階から連続した階数である必要があります。この実行パックは同じブラウザーのローカルストレージに保存される開発・確認用データです。

本番ゲームへ同梱する既定マップは `assets-src/maps/default-map-pack.json` です。通常ゲームでは同梱された家とダンジョン階を使用し、同梱されていない深い階は従来どおり自動生成します。エディターの保存領域が空の場合も、この既定パックを初期データとして読み込みます。既存の編集データは自動上書きしません。

## 素材取込と敵ロスター

右側の「素材取込」からZIP、TMX/TSX、PNGを解析できます。解析結果は承認前に保持され、候補ごとにマップ素材またはアクター、グリッド、用途、レイヤー、通行可否、敵ステータスを確認します。男性キャラクターのようなTMXはアクター候補へ分類され、マップシートには自動登録されません。必要なら候補を手動でマップ素材へ変更できます。

解析画面の「全候補を選択」後に「まとめて登録」を押すと、チェックしたマップ素材とアクターを一度に登録できます。マップ素材は `assets-src/map-tiles/sheets/imported/<取込元>/` にPNGと`.tileset.json`として保存され、アクターは `assets-src/actors/imported/<取込元>/<actorId>/` にアクション別PNGと`actor.json`として保存されます。登録後は生成カタログを再構築します。自動パレットページ作成は任意で、通常はオフのまま素材フォルダからユーザーがタイルを選び、既存の大きなパレットへ配置します。アクターはパレットには入らず、アクターカタログと敵ロスターから使用します。

登録した敵アクターは、ダンジョン階の「敵ロスター」で選択します。ロスターは出現するキャラクターの集合だけを保存し、敵数と座標は試遊開始時にランダム決定します。HP、階ごとの加算値、攻撃力はアクター定義へ保存され、敵ロスターが空なら敵なしの階になります。家のロスターは常に空でなければなりません。

「キャラクター」タブでは全アクター（敵・NPC・プレイヤー）を画像カードから選び、動作と方向を再生できます。表示名、役割、基礎HP、階ごとのHP加算、攻撃力を編集し、「能力値・役割を保存」で `assets-src/actors/actor-settings.json` に保存します。開発サーバーでは保存後に生成カタログも更新され、敵ロスターとゲーム実行時の敵定義へ反映されます。マップ編集タブの上部にはTeamsの参加者欄に似た「このマップの登場キャラクター」帯があり、ダンジョンで出現候補にする敵を画像カードで切り替えられます。家ではプレイヤー・NPCを確認用に表示します。

ダンジョン階を削除すると、後続階は自動的に前へ詰められます。階段接続は階番号で解決するため、削除確認にも接続先が変わることを表示します。新規作成・複製では最小の欠番を使い、`1, 3`の状態なら次は2階になります。重複した階番号を検出した場合は、接続が曖昧なまま新しい階を作らずエラーを表示します。
