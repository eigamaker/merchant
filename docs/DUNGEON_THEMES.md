# 手続き生成ダンジョンとテーマアセット

## 目的と責務の分離

通常の遠征ダンジョンは、遠征シードと階数から48×36セルの論理地形を生成します。生成器は画像を参照せず、床・壁、階段、部屋タグ、配置候補領域だけを決めます。描画時にテーマ定義が論理セルを`assetId + frame`へ解決するため、アセットを交換しても地形・通行・視線・既存セーブ内の配置は変わりません。

- 論理生成: `src/game/dungeonGenerator.ts`
- テーマ選択と描画計画: `src/game/dungeonThemes.ts`
- テーマ正本: `assets-src/dungeon-themes/themes.json`
- 自動生成カタログ: `src/game/dungeonThemeCatalog.generated.ts`
- ビルド時検証: `scripts/map-tile-pipeline.mjs`

手描きマップは従来どおり`authoredLayers`内に直接画像参照を持ちます。`procedural`メタデータを持つマップだけがテーマ描画の対象です。どちらも持たない旧マップは、従来の共通床・壁で描画されます。

## テーマの構造

各テーマは次の情報を持ちます。

- `id`: 永続ID。公開後は変更・削除しない
- `label`, `enabled`, `tileSize`: 表示名、有効状態、共通セル寸法
- `floorVariants`: 重み付き床候補
- `wallFrameByMask`: 壁の論理隣接16状態
- `stairsUp`, `stairsDown`: 上下階段。参照するのはパーティが立つセルの画像1枚だけです
  - 素材によっては上り階段が縦2タイルで描かれています（上半分は透過）。その場合は`height: 2`が付き、上半分は1セット上のセルへ`overhang`として描かれます
  - `height`は`npm run assets`が素材のアルファから判定して生成カタログへ書き込むので、`themes.json`には通常書きません。判定を上書きしたいときだけ明示的に`height`を書きます（詳細は`scripts/map-tile-pipeline.mjs`の`detectStackedFrames`）
- `objects`: ゲームが理由あって置くタイル。`chest`（宝箱）と`corpse`（冒険者の遺体）
  - 環境装飾と違い、実際にそこへ中身がある場所にだけ出ます。プレイヤーが「拾えるもの」と「風景」を見分けられるようにするための枠です
  - 省略可。省略すると共通の仮素材（`public/assets/objects/dungeon_objects.png`）のままになります
  - 階段と同じく縦2タイルの素材にも対応します（`height`は自動判定）
- `decorations`: 配置条件、重み、階ごとの上限、画像候補
  - `placement`は`floor` / `wall` / `wallFace` / `corner` / `deadEnd`
  - `wall`は床に接するすべての壁セル。カメラから見えない奥側の壁も含みます
  - `wallFace`はカメラに面した側の壁だけ。松明やレバーなど壁に取り付ける物はこちらを使います
  - `enabled: false`で、規則を残したまま何も置かないようにできます。落とし穴のように「本来は意味を持つべきだが、まだ仕組みがない」物を、消さずに保留しておくための項目です
  - 規則の並び順が配置乱数の種になるため、`enabled: false`にしても他の規則の配置は動きません
- `enemyPools`: `shallow`（1～2階）、`middle`（3～5階）、`deep`（6階以降）の敵ID

`cave`は必須フォールバックで無効化できません。`cave`、`ruins`、`lava`は削除せず、廃止した見た目は同じIDの参照先を代替画像へ変更してください。

## 壁マスク順

`wallFrameByMask`の配列添字0～15が、そのまま4方向の隣接マスクです。対象セルと同じく壁である隣接方向のビットを立てます。

| 方向 | ビット | 値 |
| --- | ---: | ---: |
| 北（N） | 0 | 1 |
| 東（E） | 1 | 2 |
| 南（S） | 2 | 4 |
| 西（W） | 3 | 8 |

たとえば北と西が壁なら`1 + 8 = 9`なので、配列の9番を使います。4方向すべてが壁なら15番です。同じ画像を複数のマスクへ割り当てても構いません。

## アセットの差し替え

### PNGだけを交換する場合

既存の`assetId`、16pxセル寸法、列・行数とフレーム順を維持して原本を交換し、`npm run assets`を実行します。テーマJSONは変更不要です。

### 別構成の素材パックへ交換する場合

1. 原本を`assets-src/`へ置き、既存のマップタイル取り込み設定へ登録します。
2. `npm run assets`でWeb用画像とアセットカタログを生成します。
3. `/review.html`の「ダンジョンテーマ」タブを開き、床、16壁マスク、階段、装飾の`assetId`と`frame`を画像プレビューから変更します。
4. 「テーマ定義を保存」を押します。保存先は`assets-src/dungeon-themes/themes.json`です。
5. `npm test`と`npm run build`を実行します。

生成器、移動、敵AIは変更しません。既存セーブは論理地形と`themeId`を保持しているため、次回描画から新しい参照先を使います。

### 素材パレットからの割り当て

「ダンジョンテーマ」タブ上部には、素材パレット編集で保存した16pxダンジョン用ページが画像として表示されます。

1. 階段、床、壁または装飾の設定行で「選択先」を押します。
2. 上部のパレット画像をクリックすると、そのセルの`assetId + frame`が設定先へ入ります。
3. パレット画像を設定行へドラッグして直接割り当てることもできます。
4. 変更は生成プレビューへ即時反映されます。確定時に「テーマ定義を保存」を押します。

パレットのセル位置やページ名は編集支援情報であり、テーマJSONには保存されません。テーマが保持するのは画像の`assetId + frame`なので、後からパレットを並べ替えてもテーマ設定は壊れません。素材パレット側を変更した後は「再読込」で最新状態を取得できます。

## ビルド時の受入条件

アセットビルドは次を検証し、不正なら自動除去せず失敗します。

- 必須3テーマと`cave`フォールバックが存在する
- 全テーマが16pxで、床3候補以上、壁16状態、上下階段、装飾6規則以上を持つ
- すべての`assetId + frame`がカタログ内に存在し、ダンジョンで利用可能である
- 重みと上限が正しい範囲である
- 全深度の敵IDが実行可能な敵アクターを指す

溶岩テーマでは歩行床に暗い火山岩を使用し、`yougan`系は壁・奈落側だけへ割り当てます。現在、溶岩ダメージ、罠、扉操作、水、高低差はありません。環境装飾はすべて非衝突です。

## 生成とセーブの決定性

- 3階を1区画とし、遠征開始時に保存したテーマID一覧をシード付きで並べ替えます。
- 3テーマ時は9階を1サイクルとして、各テーマが重複なしで1回ずつ登場します。次サイクルは派生シードで再度並べ替えます。
- レイアウト、装飾、敵ロスター、敵配置、商品、宝箱、遺体、NPCは別の派生乱数を使います。
- 床バリエーションと装飾は座標ハッシュで決まり、再描画やロードでも変わりません。
- セーブv12は`themeScheduleVersion`、遠征開始時の`themePoolIds`、マップの`generatorVersion`、`themeId`、`layoutSeed`を保持します。
- v5～v11の進行中ダンジョンは地形や階スナップショットを再生成せず、`cave`テーマとして移行します。

## 生成プレビューと開発用URL

テーマ編集タブの生成プレビューでは、シード、階数、テーマ、衝突表示、主経路・部屋タグ表示を確認できます。テーマを変えても論理地形と配置領域が変わらないことを比較できます。

通常モードは`procedural`です。比較用として次のクエリを利用できます。

```text
/?autostart=dungeon&dungeonSeed=4242&dungeonFloor=7&dungeonTheme=lava
/?autostart=dungeon&dungeon=fixed
/?autostart=world
```

- `dungeonSeed`: 遠征シード
- `dungeonFloor`: 1～現在の最大階（現在8）
- `dungeonTheme`: `cave`、`ruins`、`lava`のテーマ上書き
- `dungeon=fixed`: 固定マップ比較（`dungeon=manual`は保存済み試遊パックを使用）
- `autostart=world`: エディター試遊パック（manual）

生成器は1階につき8～12室、入口から出口まで5室以上、2～3分岐、35%の追加ループを狙います。50回の試行で成立しない場合は、同じレイアウトシードを使うBSPフォールバックへ切り替わります。
