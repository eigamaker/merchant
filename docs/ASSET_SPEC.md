# Dungeon Curio Merchant — アセット契約

更新日: 2026-08-13

対象: ゲームへ組み込むPNG、スプライトシート、マップ用画像

この文書は、アセットをゲームへ差し替える際に守る**固定契約**です。生成AIへ渡す文章は [ASSET_GENERATION.md](ASSET_GENERATION.md)、現在の実装状況と再生成方法は [ASSET_PIPELINE.md](ASSET_PIPELINE.md) を参照してください。

## 1. 正とする情報

矛盾がある場合は次の順で判断します。

1. `src/game/assetFrames.ts` — セル座標とフレーム番号
2. `src/game/assets.ts` — 実行時パス、フレーム寸法、アニメーション
3. この文書
4. 生成AI向けプロンプトや制作メモ

フレーム番号はすべて**左上を0とする行優先**です。画像だけを差し替え、既存のファイル名、キャンバス寸法、セル順を変更しないでください。

## 2. 共通仕様

| 項目 | 固定値 |
| --- | --- |
| ゲーム論理解像度 | 640×360px |
| マップ表示領域 | 21×12タイル、504×288px |
| 町マップ | 60×45タイル、1440×1080px |
| ダンジョン | 各階48×36タイル、入場ごとに再生成 |
| 環境セル | 24×24px |
| キャラクターフレーム | 32×32px |
| 画像形式 | PNG、RGBA、sRGB |
| 補間 | nearest-neighborのみ |
| 光源 | 左上、影は右下 |

- タイル、建物、小物にアンチエイリアス、ぼけた輪郭、セル間余白を入れません。
- ファイル名は英小文字、数字、`-`、`_`だけを使います。既存ファイルはハイフン区切りを優先します。
- 環境タイルの基準点は左上です。キャラクターは足元をセル下辺中央へ揃え、描画原点は `(0.5, 0.75)` を前提にします。
- 当たり判定、入口、調査地点は画像へ埋め込まず、ゲームデータで管理します。
- 町の建物は `town_map.png` の1枚絵に含めます。単体で描き起こす場合は1タイルのアイコンにせず、連続した1棟にします。

## 3. キャラクター

### 3.1 実行時シート

すべての主人公、NPC、護衛、人型の敵は **128×128px、4列×4行**です。1フレームは32×32pxです。

| 行 | 向き | フレーム | 内容 |
| ---: | --- | --- | --- |
| 0 | 下／正面 | 0–3 | 正面歩行 |
| 1 | 左 | 4–7 | 左向き歩行 |
| 2 | 右 | 8–11 | 右向き歩行 |
| 3 | 上／背面 | 12–15 | 背面歩行 |

- 各行の第1フレーム（0、4、8、12）が待機表示にも使われます。
- 左右は真横、上は顔と胸元が見えない背面にします。正面絵の反転、暗色化、顔だけの描き換えは不可です。
- 同一人物の頭身、頭の大きさ、足元、全高を4方向で統一します。人型キャラクターの不透明領域は高さ30〜31pxを目安にし、方向間の差は最大1pxです。
- 横向きは姿勢により幅が変わっても構いませんが、正面・背面より大きい倍率で描いてはいけません。
- 武器、鞄、髪などを含めても32pxセルからはみ出しません。足元は原則y=30〜31へ揃えます。
- コウモリなど非人型で方向によりシルエット高が変わる場合は例外を認めますが、胴体と頭部の縮尺は一定にします。

## 4. 地形

### 4.1 共通の16接続マスク

地形の1バンクは**横1行の16フレーム**です。以前の「4×4セルの1バンク」という説明は、実装の `base + mask` 参照と一致しないため廃止しました。

| ビット | 方向 |
| ---: | --- |
| 1 | 上（N） |
| 2 | 右（E） |
| 4 | 下（S） |
| 8 | 左（W） |

同じ地形が上・右・下に続く場合はマスク7、四方向すべてなら15です。バンクの列xがそのままマスク値になります。

### 4.2 `town_map.png`

町の地面は1枚の俯瞰イラストです。オートタイルの合成ではなく、絵をそのまま24pxで切り出して敷き詰めます。

- パス: `public/assets/tiles/town_map.png`
- キャンバス: 1440×1080px、60列×45行
- セル: 24×24px（フレーム番号は行優先、0〜2699）
- 形式: PNG、256色パレット（colorType 3）。他のシートのRGBA契約とはここだけ異なります
- 原画: `assets-src/town-map-source.png`（1448×1086）。`scripts/build_town_map.py` が左右4px・上下3pxを切り落として1440×1080にします。**拡大縮小はしません**

差し替える場合は、同じ構図・同じ縮尺の1枚絵を `town-map-source.png` として置き、スクリプトを再実行してから `src/game/townLayout.json` の当たり判定マスクと入口座標を絵に合わせ直します。画像だけを差し替えると、通行できない道や入れない扉が残ります。

建物、柵、木、噴水、外壁はすべてこの絵に描き込まれています。ゲーム側は別スプライトを重ねません。

#### レイアウト契約 `src/game/townLayout.json`

| キー | 内容 |
| --- | --- |
| `tile` / `width` / `height` | 24 / 60 / 45。`town_map.png` の寸法と一致させます |
| `collision` | 45行×60文字。`#`が侵入不可、`.`が通行可 |
| `buildings` | 施設のfootprint（`x`,`y`,`width`,`height`）と`entrance`。`entrance`は建物矩形の外周1セル以内かつ通行可 |
| `points` | 建物を持たないPOI（噴水広場の旅商人など） |
| `spawn` | 新規開始時の立ち位置（タイル座標） |

`TOWN_TILE_INDICES` は `y * 60 + x` の恒等写像です。特定セルだけ別のタイルへ差し替えたい場合はこの配列を書き換えます。

## 5. ダンジョン壁

- パス: `public/assets/tiles/dungeon_walls.png`
- キャンバス: 288×192px、12列×8行
- セル: 24×24px
- 固定スロット数: **15**（通常石・墓石の各バンクに同じ順序で収録）

旧見出しの「14種」は誤りです。列挙内容は中央1＋辺4＋外角4＋内角4＋柱1＋ひび1で、合計15種です。

通常石はシート行0〜3、墓石は行4〜7を使用します。各バンクのframe 0〜14が次の固定順です。

| frame | 座標 | ID | 意味 |
| ---: | ---: | --- | --- |
| 0 | (0,0) | `center` | 周囲が壁の中央 |
| 1 | (1,0) | `edgeNorth` | 北側が開いた辺 |
| 2 | (2,0) | `edgeEast` | 東側が開いた辺 |
| 3 | (3,0) | `edgeSouth` | 南側が開いた辺 |
| 4 | (4,0) | `edgeWest` | 西側が開いた辺 |
| 5 | (5,0) | `outerNorthEast` | 北東外角 |
| 6 | (6,0) | `outerSouthEast` | 南東外角 |
| 7 | (7,0) | `outerSouthWest` | 南西外角 |
| 8 | (8,0) | `outerNorthWest` | 北西外角 |
| 9 | (9,0) | `innerNorthEast` | 北東内角 |
| 10 | (10,0) | `innerSouthEast` | 南東内角 |
| 11 | (11,0) | `innerSouthWest` | 南西内角 |
| 12 | (0,1) | `innerNorthWest` | 北西内角 |
| 13 | (1,1) | `pillar` | 独立柱 |
| 14 | (2,1) | `cracked` | ひび壁 |

x3〜11・y1、および各バンクの残り領域は素材差分用の予約領域です。ランタイムは通常石を低層、墓石を4階以上または特別室で選びます。壁高、石材サイズ、接合位置、光源を15セルで統一してください。

## 6. 建物と敷地

町の建物は `town_map.png` の絵に含まれます。以下は**町描画からは外れた**副契約で、ファイルとキャンバス寸法は将来のマップエディタと差分制作のために維持します。

### 6.1 建物単体PNG（町の刷新により未使用）

`public/assets/buildings/` の連続した建物1棟。

| ファイル | 寸法 | タイル数 | 用途 |
| --- | ---: | ---: | --- |
| `tavern.png` | 192×72px | 8×3 | 酒場 |
| `guild.png` | 192×72px | 8×3 | 冒険者ギルド |
| `curio-shop.png` | 96×72px | 4×3 | 珍品店、市場、宝石店 |
| `scholar-house.png` | 96×72px | 4×3 | 研究室 |
| `arcane-shop.png` | 96×72px | 4×3 | 魔術店 |
| `noble-house.png` | 192×72px | 8×3 | 公爵邸 |
| `dungeon-gate.png` | 192×72px | 8×3 | ダンジョン入口 |

- 4×3・8×3は最終画像全体の寸法です。セルごとに独立した小屋を並べません。
- 屋根、梁、壁、影はセル境界を越えて連続させます。
- 扉は下辺中央寄りに1つ置き、扉の前はマップ側の通行可能セルにします。
- 大型建物の中央に縦線、屋根端、色差、別棟に見える段差を入れません。
- 敷地には建物外周から最低1セルの歩行余白を取り、門から入口まで道をつなげます。

現在の施設footprintと入口は `src/game/townLayout.json` を正とします。

### 6.2 モジュール式アトラス契約（町の刷新により未使用）

`town_buildings.png` と `town_building_extensions.png` は、将来のマップエディタ利用と分割配置のために保持する副契約です。

- キャンバス: 384×288px、16列×12行
- 1キット: 4×3セル
- キット内スロット: 屋根4、壁・特徴4、土台・入口4
- 正確な原点とスロットは `BUILDING_KIT_ORIGINS`、`BUILDING_KIT_SLOTS`、`WIDE_BUILDING_KIT_ORIGINS` を参照します。

大型建物は192×72pxの1枚を先に完成させてから左右4×3へ分割し、左右を別々に生成しません。

## 8. レイヤーと当たり判定

マップエディタへ移行する場合は次のレイヤー名を固定します。現在は同等の情報を `src/game/townLayout.json`（町）とダンジョン生成データが保持しています。

1. `ground`
2. `wall_back`
3. `deco_under`
4. `collision`（非表示）
5. `objects`
6. `actor`
7. `roof_front` / `wall_front`
8. `interactions`（オブジェクトレイヤー）

`interactions` は `id`、`type`、`label` を必須プロパティにします。見た目から当たり判定を推測せず、建物、柵、水、壁はゲームデータと画像の占有範囲を一致させます。

## 9. 納品判定

- PNGが指定キャンバス寸法とRGBA形式になっている。
- タイルは24px、キャラクターは32pxセルへ正確に揃っている。
- フレーム間余白、意図しない外周ピクセル、クロマキー色、白黒の縁がない。
- 人型キャラクターの4方向で頭身・全高・足元が一致している。
- 正面、左右、背面が実際に別方向の絵になっている。
- 建物を分割して再結合しても、屋根・壁・梁・影に継ぎ目がない。
- 地形の16フレームがN=1/E=2/S=4/W=8の列順に従っている。
- 通常石・墓石の壁15種がそれぞれframe 0〜14の固定順にある。
- 入口、階段、宝箱、依頼品、罠が100%表示で識別できる。
- `python scripts/build_game_assets.py`、`npm test`、`npm run build`が成功する。
