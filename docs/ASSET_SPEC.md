# Dungeon Curio Merchant — 環境アセット仕様

## 1. 共通ルール

ゲームの論理解像度は **640×360px**、地形の基本グリッドは **24×24px** です。ゲーム内でアセットを拡大・縮小しないため、納品画像はすべてこのネイティブ寸法で作成してください。

| 対象 | 仕様 |
| --- | --- |
| 形式 | 透過付きPNG（RGBA、sRGB） |
| タイル寸法 | 24×24px |
| スプライトシート | 横・縦とも24pxの整数倍。フレーム間余白なし |
| 拡大表示 | nearest-neighbor。ぼかし、アンチエイリアス、半透明の輪郭は禁止 |
| 原点 | タイルは左上、キャラクターと小物はセル中央 |
| ファイル名 | 英小文字・数字・`_`のみ。例: `town_terrain.png` |
| パレット | 1シート内で共通パレットを使う。フルカラー可だが、過度なグラデーションは避ける |
| 制作単位 | AIには「1タイル」ではなく、下記で指定する完成済みのタイルシートまたは連続建物モジュール単位で依頼する |

現在の仮アセットも24px基準です。実アセットの論理IDと配置先は [`src/game/assets.ts`](../src/game/assets.ts) を正とします。

## 2. 描画領域とレイヤー

町の可視マップ領域は **21×12タイル（504×288px）**、実マップは **48×36タイル（1152×864px）** で、プレイヤー追従カメラにより表示します。ダンジョンの可視・生成領域は21×12タイルを維持します。右側HUDと下部メッセージログはマップアセットを置かない領域です。

環境を描くときは、下から上へ次の順で扱います。

1. `ground` — 草、土、石床、水、木床など。常に通行可能か、地形属性だけを持つ。
2. `wall_back` — 壁の奥側、崖、建物の背面。キャラクターの後ろに描く。
3. `deco_under` — 草花、ひび、影、敷物など。通行可。
4. `object` — 宝箱、棚、看板、柵、建物の扉。通行可否・調査地点を持つ。
5. `actor` — プレイヤー、NPC、敵。
6. `wall_front` / `roof_front` — 手前側の壁・屋根。キャラクターより上に描く。室内へ入る場合は半透明化または非表示にする。

当たり判定は見た目から推測せず、マップの `collision` レイヤーで管理します。アート上は通れそうでも `collision` に値があれば通れず、逆も可能です。

建物は複数セルをまたぐ**ひとつの建造物**です。屋根、壁、窓、扉、影、看板をセル単位で別々にデザインせず、まず連続した建物として設計し、その後24pxグリッドで切り分けます。隣接セルの境界に太い線、余白、屋根の切れ目、模様の不連続を作ってはいけません。

## 3. 地形タイルセット

### 共通のオートタイル規則

地形素材ごとに **4×4セル、16タイル**を1バンクとして作成します。インデックスは四方向の同素材隣接をビットで表します。

| ビット | 隣接方向 |
| ---: | --- |
| 1 | 上（N） |
| 2 | 右（E） |
| 4 | 下（S） |
| 8 | 左（W） |

例: 上・右・下が同素材なら `1 + 2 + 4 = 7` 番フレームです。角の見栄えを改善する斜め差分は、同じ16セル内の表現で吸収します。ランダム差分は別バンクに置き、ゲーム側から明示的に選択します。

### `public/assets/tiles/town_terrain.png`

- キャンバス: **384×192px（16列×8行）**
- 1バンク: 4列×4行（96×96px）
- 左上から右へ、次の順で配置する。

| バンク | セル範囲 | 内容 | 通行 |
| ---: | --- | --- | --- |
| 0 | x0–3, y0–3 | 草地 | 可 |
| 1 | x4–7, y0–3 | 土の道 | 可 |
| 2 | x8–11, y0–3 | 石畳 | 可 |
| 3 | x12–15, y0–3 | 木床 | 可 |
| 4 | x0–3, y4–7 | 浅瀬／水際 | 原則不可 |
| 5 | x4–7, y4–7 | 花壇・耕地 | 可 |
| 6 | x8–11, y4–7 | 地下入口周辺の岩地 | 可 |
| 7 | x12–15, y4–7 | 予備（祭り・季節差分） | 定義時に指定 |

草・道・石畳の色相と明度は離し、移動可能な経路が一目で判別できるようにします。町は自由移動なので、道タイル自体は移動を強制しません。

### `public/assets/tiles/dungeon_terrain.png`

- キャンバス: **384×192px（16列×8行）**
- バンク0: 通常の石床、バンク1: 湿った石床、バンク2: 古い敷石、バンク3: 墓所床。
- バンク4以降は特殊部屋用（魔法陣、浅い水、瓦礫床、祭壇床）。
- 床はアイテム、敵、罠、階段の視認性を優先し、中央部のコントラストを抑える。

### `public/assets/tiles/dungeon_walls.png`

- キャンバス: **288×192px（12列×8行）**
- 上段4行: 通常石壁、下段4行: 墓所・古代遺跡壁。
- アクティブ領域は左上の **12×4セル**。各素材は、中央1＋辺4＋外角4＋内角4＋柱1＋ひび1の **15種** を置く。旧版の「14種」は列挙との不一致による記載誤りであり、本仕様では15スロットへ補正する。
- 正確なセル座標は [`src/game/assetFrames.ts`](../src/game/assetFrames.ts) を正とする。1行目に中央〜内角南西の12種、2行目のx0〜x2に内角北西・柱・ひびを置く。x3〜x11、およびy2〜y3は将来差分用の予約領域。
- 壁の当たり判定はすべて不可。壁の手前面は `wall_front`、上面は `wall_back` に分ける。
- 通路の幅は原則1タイル。キャラクターやアイテムのシルエットを壁面へはみ出させない。

## 4. 町の建物セット

### `public/assets/tiles/town_buildings.png`

- キャンバス: **384×288px（16列×12行）**
- すべて24×24pxセルで作るモジュール式タイルセット。
- 下記の「建物キット」を各 **4×3セル（96×72px）** で割り当てる。大型施設はキットを横に連結して組み立てる。

| キット | 用途 | 必須セル |
| --- | --- | --- |
| `wood_shop` | 珍品店・道具店 | 屋根左／中／右、正面壁、扉、窓、看板、影 |
| `stone_public` | ギルド・研究室 | 石屋根、石壁、扉、掲示板、窓、影 |
| `warm_inn` | 酒場 | 暖色屋根、看板、扉、窓、煙突、影 |
| `noble_house` | 公爵邸 | 高級屋根、紋章、柱、扉、窓、影 |
| `arcane_shop` | 魔術店 | 尖塔屋根、魔法窓、吊り看板、扉、影 |
| `market_props` | 宝石店・屋台 | テント、台、布、箱、看板、影 |
| `dungeon_entrance` | ダンジョン入口 | 岩壁、階段口、松明、看板、影 |
| `shared_props` | 共通 | 柵、街灯、樽、木箱、植木、旗 |

建物キットのシート内座標は以下に固定します。各キットの原点から、共通の4×3必須セル配置を適用します。

| キット | 原点セル（x, y） | 占有フレーム番号 |
| --- | ---: | ---: |
| `wood_shop` | (0, 0) | 0–3, 16–19, 32–35 |
| `stone_public` | (4, 0) | 4–7, 20–23, 36–39 |
| `warm_inn` | (8, 0) | 8–11, 24–27, 40–43 |
| `noble_house` | (12, 0) | 12–15, 28–31, 44–47 |
| `arcane_shop` | (0, 3) | 48–51, 64–67, 80–83 |
| `market_props` | (4, 3) | 52–55, 68–71, 84–87 |
| `dungeon_entrance` | (8, 3) | 56–59, 72–75, 88–91 |
| `shared_props` | (12, 3) | 60–63, 76–79, 92–95 |

「占有フレーム番号」はシート全体の行優先番号です。各キットの12セルは16列シート上で連続しないため、範囲ではなくこの列挙を正とします。正確な参照は `buildingKitFrame(kit, slot)` を使います。

| キット内セル | 座標（相対） | 必須内容 |
| --- | ---: | --- |
| `roofLeft`, `roofMidLeft`, `roofMidRight`, `roofRight` | (0–3, 0) | 屋根・岩壁上端・テント上部 |
| `facadeLeft` | (0, 1) | 左側の壁面 |
| `featureLeft`, `featureRight` | (1–2, 1) | 窓、看板、紋章、魔法窓など施設固有の特徴 |
| `facadeRight` | (3, 1) | 右側の壁面 |
| `baseLeft`, `baseRight` | (0 / 3, 2) | 下端、影、土台 |
| `entrance` | (1, 2) | 必ず通行・会話地点に対応する扉または入口 |
| `thresholdOrProp` | (2, 2) | 入口脇の敷居、箱、掲示、岩など |

町の建物は次の標準サイズで配置します。1マスだけで機能施設を表現することは禁止し、入口は建物の外側セルに置きます。

| 施設 | 標準サイズ | 入口セル | 接触判定 |
| --- | ---: | --- | --- |
| 珍品店・道具店・魔術店・宝石店 | 4×3 | 下辺中央 | 入口の前24px以内で会話 |
| 酒場・冒険者ギルド・公爵邸 | 8×3（4×3キットを横連結） | 下辺中央 | 同上 |
| 研究室 | 4×3 | 下辺中央 | 同上 |
| ダンジョン入口 | 8×3（岩壁キットを横連結） | 階段前 | 階段前24px以内で入場 |

建物の屋根は上2行、壁・扉は下1〜2行を基本にします。衝突は壁と屋根の全体ではなく、地図の `collision` レイヤーで設定します。町の移動はリアルタイムであり、建物・柵・水だけが移動を妨げます。

### `public/assets/tiles/town_building_extensions.png`

酒場、ギルド、公爵邸、ダンジョン入口のような横幅8セルの施設は、`town_buildings.png` の4×3キットを機械的に繰り返して作りません。**1棟の連続した8×3セル（192×72px）建築**を作り、左右4×3セルへ切り分けます。

- キャンバス: **384×288px（16列×12行）**。
- 左右の境界（x3/x4、x11/x12）に縦線、段差、別々の屋根端、色差を入れない。
- 屋根の外端は8セル全体の左端・右端だけに置く。中央の6セルは連続した屋根瓦・梁・壁模様とする。
- 各建物の扉は下辺の中央寄りに1つだけ置く。扉前の1セルは建物画像に含めず、マップ側の通行可能な入口セルとして空ける。

| 建物ペア | 連続領域 | 左右への分割 | 用途 |
| --- | --- | --- | --- |
| `warm_inn` | x0–7, y0–2 | 左 x0–3 / 右 x4–7 | 酒場 |
| `stone_public` | x8–15, y0–2 | 左 x8–11 / 右 x12–15 | 冒険者ギルド |
| `noble_house` | x0–7, y3–5 | 左 x0–3 / 右 x4–7 | 公爵邸 |
| `dungeon_entrance` | x8–15, y3–5 | 左 x8–11 / 右 x12–15 | ダンジョン入口 |
| 予約 | y6–11 | 未使用 | 季節・破損・夜景差分 |

このシートの正確なフレーム参照は `wideBuildingKitFrame(kit, side, slot)` を使用します。

### `public/assets/tiles/town_objects.png`

- キャンバス: **384×192px（16列×8行）**。
- x0–3, y0–3: 柵の四方向接続16種。接続ビットは地形と同じ `N=1 / E=2 / S=4 / W=8` とする。
- x4–7, y0: 閉じた門4方向、x4–7, y1: 開いた門4方向。閉門・開門どちらも**1セル幅の通過口**として描く。
- x4–7, y2–3: 柵柱、壊れ柵、短い柵、角の飾り。x8–11, y0–3: 木、岩、花、街灯、井戸、看板。
- x12–15, y0–3: 畑、作物、家畜、樽、木箱。x0–7, y4–5: 露店、布屋根、商品台。x8–15, y4–5: 桟橋、杭、小舟。y6–7は予約。
- 柵は各セルの外縁に沿って連続させ、柱位置と横桟の高さをすべての接続セルで一致させる。門だけを通行可能にする。木・岩・水は画像と同じ `collision` 情報を必ず持たせる。
- 町の固定レイアウトと入口座標は [`src/game/townMap.ts`](../src/game/townMap.ts) を正とする。

### 敷地の組み立て規則

敷地は「建物を置いた草地」ではなく、柵・門・道・用途小物まで含む一区画として組み立てます。建物自体は4×3または8×3セル、敷地はその周囲に最低1セルの歩行余白を取り、門から入口まで道で接続します。

| 区画 | 実装サイズ | 必須構成 |
| --- | ---: | --- |
| 農地 | 13×8セル | 閉じた柵、南辺の1セル門、耕地・作物・水桶・かかし |
| 家畜小屋 | 12×7セル | 閉じた柵、西辺の1セル門、土の地面・家畜・飼い桶・干し草 |
| 公爵邸敷地 | 12×12セル | 閉じた柵、西辺の1セル門、8×3セル邸宅、庭木・旗・石畳の導線 |
| 市場 | 中央広場内 | 2〜4セル幅の露店を複数、通路を塞がない配置、樽・商品台・布屋根 |

## 5. マップデータ仕様

町をTiledなどのマップエディタで作る場合は、以下のレイヤー名を固定します。

| レイヤー | 型 | 用途 |
| --- | --- | --- |
| `ground` | タイル | 基本地形 |
| `wall_back` | タイル | 奥側の壁・崖・建物背面 |
| `deco_under` | タイル | 通行可能な装飾 |
| `collision` | タイルまたはオブジェクト | 通行不可領域。描画しない |
| `interactions` | オブジェクト | 入口、NPC、調べる場所。24px半径を基本にする |
| `objects` | タイル／オブジェクト | 宝箱、看板、棚、柵 |
| `roof_front` | タイル | 手前屋根・壁。actorより前に描く |

`interactions` のオブジェクトプロパティは `id`、`type`、`label` を必須とします。例: `id=shop`, `type=facility`, `label=珍品店`。

## 6. 生成AIへの制作指示

### 依頼と納品の手順

生成AIへは完成マップ全体や、複数施設が混在する一覧画像を依頼しません。**1リクエストにつき1つの連続モジュール**（4×3建物、8×3建物、柵セット、露店セットなど）に限定します。AI出力はデザイン原画であり、納品時には以下の手順で24pxセルへ整形します。

1. 指定の連続モジュールを、背景色 `#FF00FF` の大きな整数倍率で生成する。文字、UI、キャラクター、タイル境界線は入れない。
2. 最近傍補間で最終サイズへ縮小し、`#FF00FF` を透過へ変換する。
3. 指定セル境界で分割して各シートの座標へ配置する。分割後の隣接セルを再結合し、屋根・壁・柵に継ぎ目がないことを確認する。
4. 透明縁、ぼけ、アンチエイリアス、はみ出した影、セル間の余白を修正してからPNGで納品する。

| 依頼対象 | 生成原画サイズ | 最終連続モジュール | 切り出し |
| --- | ---: | ---: | --- |
| 小型建物 | 1536×1152px | 96×72px（4×3セル） | 24×24pxを12セル |
| 大型建物 | 3072×1152px | 192×72px（8×3セル） | 24×24pxを24セル、左右4×3へ分割 |
| 1セル小物 | 384×384px以上 | 24×24px | 1セル、または同寸法のバリエーション群 |
| 柵16接続 | 1536×1536px | 96×96px（4×4セル） | 24×24pxを16セル |

光源は常に**左上**、影は**右下**へ落とします。視点は見下ろし寄りの3/4ビューで、アイソメトリック、正面図、強い遠近法、写実的な滑らかグラデーションは禁止します。最終24pxサイズで外周線は原則1px、屋根・壁・草の陰影は2〜4色の塊で読めるようにします。

### 共通プロンプト

以下を各依頼の先頭へ付け、`[対象]`、`[配色]`、`[固有要素]` だけを書き換えます。

> 2D見下ろし型ファンタジーRPG用のピクセルアート素材。対象は `[対象]`。24pxグリッドへ正確に縮小・分割するため、輪郭はくっきりしたピクセル、アンチエイリアスなし、滑らかなグラデーションなし。左上からの光、右下へ短い影。緑豊かな村に合う暖かな木材、石、土、くすんだ草色、落ち着いた青緑の配色。背景は単色 #FF00FF。UI、文字、ロゴ、人物、動物以外の不要な物、タイルの罫線、額縁、余白は入れない。複数タイルの場合、セル境界をまたいで屋根瓦・梁・壁模様・影が自然につながる1棟の連続物として描く。

### 建物用プロンプト

4×3建物では `[固有要素]` を、8×3建物では「左右に分かれた2棟」ではなく**横長の1棟**であることを必ず指定します。

> `[対象]` の連続建物モジュール。最終サイズは `[96×72px または 192×72px]`、24pxグリッドで `[4×3 または 8×3]` セル。上段は連続した屋根、中段は壁・窓・看板、下段は壁・扉・土台。扉は下辺中央寄りに1つだけ置き、扉の外側1セルは画像に含めない。`[配色]`。`[固有要素]`。屋根の端は建物全体の外側だけに置き、中央セルに屋根の端・切断線・段差を作らない。建物全体の下に右下向きの短い影を置く。

依頼例:

> 大型酒場の連続建物モジュール。最終サイズ192×72px、24pxグリッドで8×3セル。赤茶の瓦屋根、暖色の漆喰壁、中央寄りの木扉、窓から漏れる黄橙色の光、左端に短い煙突、控えめな吊り看板。8セルをまたぐ屋根と梁を切れ目なく描き、中央の左右境界に線や段差を入れない。

### 柵・敷地・小物用プロンプト

> 木製の村の柵タイルセット。24pxセル16枚を4×4で構成し、N=1/E=2/S=4/W=8の四方向接続に従って、端・直線・T字・十字・角が途切れずつながる。各セルの同じ位置に木柱と横桟を置く。左上光・右下影。柵の外縁に草と土を少量つけるが、隣接セルとの接続部は空ける。門は別の1セルとして、閉門と開門を4方向で描く。背景 #FF00FF、文字や罫線なし。

> 村の農地・家畜小屋・公爵邸の敷地用小物。24pxセルのピクセルアート。畑の畝、作物、水桶、かかし、干し草、飼い桶、旗、庭木、石畳、樽、木箱を個別セルとして描く。建物や柵を含む完成マップにはせず、各セル単体でも周囲の24pxタイルと自然につながる配置にする。

### ダンジョン用プロンプト

> 地下遺跡ダンジョン用の24pxピクセルアートタイル。見下ろし3/4ビュー、青灰色の石、湿った苔、土埃、控えめな茶色の瓦礫。床の中央はアイテム・敵・罠が読みやすい低コントラストにし、壁は上面と手前の立ち上がりを分ける。壁は中央、上下左右辺、外角4、内角4、柱、ひびの計15種類を同じ石材・光源・壁高で統一する。血痕や強い発光、文字、人物、UIは入れない。

## 7. AI生成を利用する場合のモデル方針

AIによる下絵・テクスチャ生成を導入する場合は、**`gpt-image-2-2026-04-21` を既定かつ固定モデル**とします。新規生成で `gpt-image-1-mini` を選ぶことは許可しません。既存の旧モデル生成物は再生成を強制せず、メタデータに `legacy` として出所を保持します。

- GPT Image 2は柔軟な画像サイズと高忠実度の画像入力をサポートする現行モデルであり、固定スナップショットも提供されています。[公式モデル仕様](https://developers.openai.com/api/docs/models/gpt-image-2)
- `gpt-image-1-mini` は公式カタログで非推奨です。既存成果物の後方互換だけに限定します。[公式モデル仕様](https://developers.openai.com/api/docs/models/gpt-image-1-mini)
- 生成元は大きな整数倍率のシートにし、納品前に24pxグリッドへ最近傍縮小する。透明背景が利用できない経路では、予約したクロマキー色（#FF00FF）を透過へ変換してから、フレーム境界と色残りを検査する。
- 生成メタデータには `model`、`prompt`、`source_image`、`scale`、`chroma_key`、`processed_at` を残す。ゲームコードは生成モデルに依存せず、上記フレーム座標契約だけに依存する。

## 8. 納品チェックリスト

- すべてのセルが24×24pxグリッドに正確に揃っている。
- スプライトシート端に余白、フレーム間の隙間、勝手なトリミングがない。
- 透明部分に白・黒の縁が残っていない。
- 壁・建物・大きな小物の影は、専用の影セルか下側の描画レイヤーへ分離している。
- 入口、扉、宝箱、罠、階段は床との明度差があり、プレイ中に識別できる。
- 衝突・入口・屋根前面の情報は画像だけでなくマップレイヤーへ設定されている。
- 実ゲームの100%表示と2倍／3倍表示で、輪郭がぼやけず読みやすい。
- 大型建物は、左右の4×3セルを再結合した時に屋根・壁・影が完全につながり、中央に端材や二重の屋根端がない。
- 柵は16接続を並べた時に柱・横桟が連続し、閉じた敷地には少なくとも1つの門セルがある。
