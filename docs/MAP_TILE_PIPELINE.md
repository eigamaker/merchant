# マップ素材パイプライン

## 素材の追加

スプライトシートと同名の設定ファイルを `assets-src/map-tiles/sheets/` に置きます。

```text
stairs.png
stairs.tileset.json
```

設定ファイルは `version`（`1`）、`id`、`label`、`tileSize`（`16` または `32`）、`margin`、`spacing`、`mapKinds`（`home` / `dungeon`）、`defaultLayer`、`defaultWalkable` を持ちます。画像は8-bit RGBAのPNGで、余白と間隔を除いた領域がタイルサイズの整数倍でなければなりません。

取込が生成したシートは、どう作られたかを `sourceFormat`（`grid` / `wolf-autotile` / `section-catalog`）で記録します。`wolf-autotile` のシートは `autotile`（`scheme` は `blob47`、`animationFrames` は正の整数）も持ち、幅はちょうど47タイル、行数はアニメーションのコマ数でなければなりません。

同じ `id` は一度しか登録できません。PNGだけ、またはJSONだけのペアはエラーになります。

## ZIP／TMX／PNGの取込

`npm run edit` で開く `/review.html` の「素材パレット編集」からZIP、TMX/TSX一式、またはPNGを解析できます。複数ファイルを選択した場合はブラウザー側で一時ZIPにまとめます。CLIでは次の診断コマンドも使えます。

```powershell
npm run assets:inspect -- C:\path\to\pack.zip
```

TMXはtilesetの画像・グリッド情報を読み取り、アニメーション定義とアクション名が揃うものはキャラクター候補へ分類します。完成済みTMXマップのセル配置は今回のマップJSONへ自動変換しません。参照画像不足、寸法不一致、曖昧な分類は警告としてレビュー画面に残します。

取込はまずシートの形式を判定します。判定順は「ウディタのオートタイル」「見出し帯付きカタログ」「通常グリッド」で、どれにも当てはまらない場合は `unknown` として保留し、セルサイズを推測しません。以前は16/32pxグリッドに割り切れるかどうかだけを見ていたため、16×80のオートタイルが「1列×5行」の正当なグリッドとして警告なく登録されていました。

レイヤー、通行可否、margin/spacingは承認前に変更できます。減色PNGは正規化されたRGBAコピーを生成します。

### ウディタのオートタイル

`(16 × アニメーションコマ数) × 80` のPNGはウディタ（WOLF RPG Editor）のオートタイルです。5行はタイルではなく、1枚のタイルの4象限を埋めるための部品で、上から順に「外側の角」「縦の辺」「横の辺」「内側の角」「塗り」です。横方向の余分な列は全体のアニメーションコマになります。

取込はこれを47タイルのblobセットへ展開し、`47 × コマ数` の通常グリッドとして保存します。フレーム番号は `アニメーションコマ × 47 + frameByMask[近傍マスク]` で求めます。256エントリの対応表は方式ごとに共通なので、シートごとには保存せず `src/game/autotile.ts` が持ちます（`scripts/autotile.mjs` と同一であることをテストが保証します）。

### 見出し帯付きカタログ

`base.png` のように、カテゴリの見出しが画像へ焼き込まれた大きなシートは、全幅の平坦な帯を境にセクションへ分割します。帯の色が3行以上で繰り返される場合だけカタログとみなすため、平坦なタイルが並ぶ普通のシートは分割しません。見出しはピクセル文字なので読み取らず、切り出した帯の画像を取込画面へ表示して、作者が一度だけ名前を付けます。

### `.tile` のタイルセット構成

WOLF RPG Editorの`.tile`から、作者自身のタイルセット構成（名称と画像の並び）を読み取ります。文字列は `<uint32 LE 長さ><Shift-JISのバイト列>` で、長さはNUL終端を含みます。読み取った構成は `tileGroups` として解析結果に含め、ダンジョンテーマの下書きとして利用できます。自動接続の衝突判定など、それ以外の設定は使用しません。

解析結果は30分間だけ開発サーバーの一時領域に保持され、「まとめて登録」を押した候補だけが`assets-src/map-tiles/sheets/imported/`または`assets-src/actors/imported/`へ保存されます。マップ素材は既定で素材別パレットページも作成します。不要な場合だけ登録前にチェックを外します。原本のSHA-256、参照パス、README/ライセンスの有無は`imports.json`へ記録します。

アクターを登録した場合は、開発サーバーが同時にアクター生成処理を実行し、`public/assets/actors/generated/`と`src/game/actorAssetCatalog.generated.ts`を更新します。アクター画像はマップパレットには追加せず、敵ロスター／実行時アクターカタログから参照します。

## パレット

`assets-src/map-tiles/palettes.json` が正本です。ページは `id`、`label`、`mapKind`、`tileSize`、`width`、`height`、`cells` を持ちます。セルには `x`、`y`、`assetId`、`frame`、`layer`、`walkable` を保存します。空白セルは `cells` に含めません。

セルには仕分けの情報も持てます。`role` は用途（`floor` / `wall` / `prop` / `stairs` / `liquid`）、`status` は採否（`ready` / `unsorted` / `rejected`）、`note` は不採用の理由です。いずれも省略可能で、`role` が無いセルは「未仕分け」として数えます。ダンジョンテーマの素材ピッカーは `role` で絞り込み、`rejected` のセルは候補から外します。

パレットは手動マップの有無に依存しません。ローグライクの自動生成では、ダンジョンテーマがパレット上の素材を参照して床、壁、階段、装飾を設定します。手動マップ編集は任意の確認・試作用として残しています。

## ダンジョンテーマの壁

テーマは壁を2通りで指定できます。`wall` に展開済みオートタイルの `assetId` を1つ書くと、8近傍から自動的にタイルが決まります。`wall` を書かない場合は従来どおり `wallFrameByMask` に16個のフレームを並べます（マスクは N=1 / E=2 / S=4 / W=8）。

`wall.face` を指定すると、南が床の壁セル（手前を向いた面）だけがその絵に差し替わります。`wall.faceHeight` を `2` にすると面は縦2セル分になり、参照したフレームが上半分、その1行下のフレームが下半分になります。上半分は描画プランの `overhang` に入り、キャラクターと同じY順で並ぶため、壁が手前に立って奥のキャラクターを隠します。

床と壁は16pxグリッドで並ぶ必要がありますが、装飾は32pxの素材も使えます。32pxの絵は1枚で2×2セルを占め、左上のセルを基準に配置します。

自動接続の方式はテーマではなく素材側の属性です。同じシートをどのテーマで使っても並びは変わらないため、`autotile` はシートの `.tileset.json` が持ちます。

## 生成

```powershell
npm run assets
```

生成物は専用ディレクトリ `public/assets/map-tiles/generated/` と `src/game/mapAssetCatalog.generated.ts` に出力されます。生成ディレクトリ以外は掃除しません。`npm run dev`、`npm test`、`npm run build` は開始前に自動生成します。

原本を削除すると、次回生成時に対応する生成画像・カタログからも消えます。PNGと`.tileset.json`は必ずセットで削除してください。マップパレットに残っている削除素材のセルは自動的に除去します。アクターも、アクターのフォルダを削除して再生成すれば生成カタログから除去されます。

開発サーバーでは `GET /__map-editor/palettes` で正本を読み取り、`PUT /__map-editor/palettes` に検証済みのパレットJSONを送ると、正本を一時ファイルから置換して再生成します。このAPIはVite開発サーバーにだけ登録され、本番ビルドには含まれません。旧クライアント向けに `GET/POST /__map-tiles/palettes.json` も利用できます。素材シートの追加・変更・削除は開発サーバーが監視し、成功時に全ページを再読込します。

## 難易度と出現表

敵の数値はデータではなくコードが決めます。`src/game/dungeonDifficulty.ts` に、系統ごとの基準値、格（ティア）の倍率、深さの伸び、強敵の倍率、階ごとの遭遇予算、そして深さの帯（shallow／middle／deep）の唯一の定義が入っています。アクターは「何であるか」（`archetype`）と「どれだけの格か」（`tier`）だけを持ちます。

以前はHPだけが階層で伸び、攻撃力は固定でした。また深さの帯が `dungeonThemes.ts` と `engine.ts` で食い違っていました（6階と7階）。いずれも解消しています。

テーマの `spawns` は出現表です。各行は `actorId`、`minFloor`、任意の `maxFloor`、`weight`、任意の `role`（`common` / `elite`）と `maxPerFloor` を持ちます。1階を空にする表は検証で拒否します。旧来の `enemyPools`（3段階）も読めますが、`spawns` があればそちらが優先されます。

配置は固定体数ではなく `encounterBudget(floor)` の予算を消費する形です。格が高い敵ほどコストが大きいため、強い敵を入れた階は体数が減ります。
